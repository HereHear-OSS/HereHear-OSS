# ADR-0001: 백엔드로 Supabase를 사용한다

- 상태: 승인
- 날짜: 2026-11-14
- 결정자: @yuri473
- 관련 토론: 없음

## 배경 (Context)

HereHear는 현재 위치에 음악과 메시지를 남기고, 반경 2km 안의 다른 여행자가 발견하는 서비스다.
이를 위해 음악 등록 데이터 저장, 사용자 인증, 위치 기반 조회가 필요하다.
프론트엔드(Vite) 개발에 집중해야 하는 소규모 프로젝트라, 서버를 직접 만들고 운영할 여력이 적다.

## 결정 (Decision)

데이터베이스, 인증, API를 Supabase로 구성한다.

## 검토한 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| Supabase | PostgreSQL 기반이라 위치 조회를 SQL로 처리할 수 있음, 인증과 API 기본 제공 | 서비스에 종속됨, 무료 요금제 한도 |
| Firebase | 문서와 예제가 많고 실시간 동기화가 쉬움 | 반경 조회 같은 위치 질의가 번거로움 |
| 직접 서버 구축 | 구조를 자유롭게 설계 가능 | 개발과 운영 부담이 큼 |

## 결과 (Consequences)

- 좋은 점: 서버 코드 없이 프론트엔드에서 바로 데이터를 읽고 쓸 수 있다.
- 감수할 점: 접근 권한을 데이터베이스 정책(RLS)으로 꼼꼼히 관리해야 한다.
- 후속 작업: 반경 안 동일 곡 중복 등록 제한을 데이터베이스 쪽에서 검사한다.

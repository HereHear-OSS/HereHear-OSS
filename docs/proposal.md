학기 프로젝트 제안서 — HereHear

1\. 프로젝트명과 목표

HereHear: 여행지에 남기는 음악 발자국



여행자가 현재 위치에 음악과 짧은 메시지를 남기고, 다른 여행자가 그 장소 반경 2km 안에서 음악을 발견하고 들으며 추억을 저장하는 위치 기반 음악 공유 웹 서비스다. 한 학기 동안 모바일 화면에서 사용할 수 있는 MVP를 개발한다.



2\. 문제 정의

사진과 글만으로는 여행 당시의 분위기와 감정을 충분히 전달하기 어렵다. 또한 여행자는 자신이 방문한 장소에서 다른 사람이 어떤 추억을 남겼는지 발견할 기회가 적다. HereHear는 장소에 음악과 메시지를 연결해 여행의 감정을 남기고, 현장에 도착한 여행자가 그 기록을 발견하도록 한다.



이 문제는 프로젝트의 출발 가설이다. 초기 사용자 인터뷰에서 장소에 음악을 남기려는 의향과 실제 방문 중 발견 기능의 유용성을 확인한다.



대상 사용자: 여행지에서 감정을 기록하고 싶은 여행자와, 같은 장소에서 다른 사람의 추억을 발견하고 싶은 여행자.



핵심 흐름: 현재 위치 확인 → 곡과 메시지 등록 → 다른 여행자가 2km 안에 진입 → 지도 발자국 선택 → 음악 재생 → 좋아요 또는 즐겨찾기.

3\. 핵심기능 3개

| 기능 | 사용자 동작 | 완료 기준 |

|---|---|---|

| 현재 위치에 음악 등록 | 위치 권한을 허용하고 곡과 메시지를 입력해 등록한다. | GPS 위치로만 등록하며, 반경 2km 안 동일 곡은 ‘이미 등록된 노래입니다’를 표시하고 저장을 차단한다. |

| 지도에서 음악 발견·재생 | 발자국 마커를 선택하고 곡과 메시지를 확인한 뒤 음악을 듣는다. | 거리별 활성 상태가 일치하고, 다른 세션에서 등록한 곡을 반경 안에서 조회하고 실제 재생한다. |

| 좋아요·즐겨찾기로 추억 저장 | 발견한 음악에 좋아요를 누르고 즐겨찾기 목록에 저장한다. | 중복 좋아요가 집계되지 않고 취소할 수 있으며, 같은 브라우저로 재접속해 저장 상태를 확인한다. |

4\. 기술 스택 초안

| 영역 | 선택 | 용도 |

|---|---|---|

| 웹 앱 | Next.js, React, TypeScript | 모바일 중심 화면과 서버 API 구현 |

| 스타일 | CSS | 지도, 바텀시트, 등록 폼과 저장 목록 구현 |

| 지도·위치 | Leaflet, OpenStreetMap 기반 타일, 브라우저 Geolocation | 지도 표시, 현재 위치 확인, 발자국 마커 표시 |

| 공유 저장소 | Supabase PostgreSQL + PostGIS | 여행자 간 등록 데이터 공유, 미터 단위 거리 조회 |

| 익명 식별 | Supabase 익명 인증 | 로그인 화면 없이 좋아요·즐겨찾기 소유자 식별 |

| 음원 | 사용 허가된 시연 음원 카탈로그 + HTML audio | 곡 ID로 선택하고 실제 오디오 재생 |

| 검증 | Vitest, Playwright | 거리·중복 규칙과 사용자 흐름 검증 |

| 협업·배포 | Git, GitHub, Vercel | 변경 이력 관리와 HTTPS 시연 환경 |

5\. 구현 정책 초안

다음 정책은 제공된 계획의 미정 사항을 구현 가능한 형태로 제안한 가정이다. 2주차에 검토하고 READ.md에 확정 정책을 기록한다.



반경은 2,000m 이하를 포함한다. 동일 곡 ID의 기존 등록이 이 거리 안에 있으면 등록을 막고, 다른 곡은 허용한다.

등록 좌표는 최신 GPS 측정값만 사용한다. 지도에서 임의로 찍은 위치는 등록 좌표로 사용하지 않는다.

위치 측정은 watchPosition으로 갱신한다. 측정값이 30초보다 오래되거나 정확도 오차가 100m를 넘으면 등록·새 재생을 막고 재측정을 안내한다.

반경 밖 마커는 흐린 발자국과 접근 제한 안내만 표시한다. 곡·메시지 상세 조회와 재생은 반경 안에서 허용한다.

반경 이탈 또는 위치 유효성 상실 시 재생을 중지한다. 즐겨찾기는 유지하지만 다시 재생하려면 반경 안에 있어야 한다.

메시지는 앞뒤 공백 제거 후 1\~200자로 제한한다. 곡 ID는 서버의 허용 카탈로그에서 검증하고 메시지는 일반 텍스트로 표시한다.

익명 사용자당 등록 기록 하나에 좋아요·즐겨찾기를 각각 한 개만 허용한다. 다시 누르면 취소하며, 저장 실패 시 성공 표시를 유지하지 않는다.

재접속 상태는 같은 브라우저의 익명 세션이 유지되는 범위에서 보존한다. 브라우저 데이터 삭제·다른 기기 간 복원은 제외한다.

서버에서 곡별 트랜잭션 잠금 후 거리 중복 검사와 등록을 처리해 동시 요청의 중복을 막는다. 클라이언트는 저장 중 버튼을 잠근다.

클라이언트 위치 정보는 조작 가능하므로 실제 현장 방문을 완전히 증명하는 기능은 MVP 범위에 포함하지 않는다.



6\. 데이터와 공유 구조

곡 카탈로그: 곡 ID, 제목, 아티스트, 재생 참조, 사용 권한 정보.

등록 기록: 등록 ID, 곡 ID, 메시지, 위도·경도, 등록 시각, 익명 작성자 ID.

좋아요·즐겨찾기: 익명 사용자 ID와 등록 ID의 조합을 고유 키로 저장한다.

모든 여행자는 서버 API를 통해 같은 데이터베이스의 등록 기록을 조회한다. 기기 내부 저장만으로 공유를 대체하지 않는다.

서버는 익명 세션과 입력값을 검증하고, 거리 정책에 따라 상세 조회와 저장을 처리한다. 데이터 접근 정책을 설정하고 비밀 키는 서버에만 둔다.
